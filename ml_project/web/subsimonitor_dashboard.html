ML model insights — trained on real coal-mine hazard data

The AI Risk Engine box in the pipeline above isn't a placeholder — it's backed by a model actually trained and evaluated on the UCI seismic-bumps dataset (Sikora & Wrobel, 2010): 1,809 shift-level seismic/seismoacoustic readings from a Polish coal mine, labelled for whether a dangerous high-energy bump occurred in the next shift. ~6% of shifts are hazardous — the same kind of rare-event imbalance our CRITICAL class has.

These numbers are honest, not tuned to look good: 6%-positive hazard forecasting is a genuinely hard problem, and published work on this exact dataset reports similar F1 in the 0.2-0.35 range. That's exactly why the twin never lets the AI score fire alone — rules R1-R6 and the 2-of-3 corroboration gate are an independent second check.

The ESP32 can't run a 400-tree forest, so a depth-4 decision tree was distilled from the same data on 4 edge-measurable features and exported straight to C — this is rule R1-R6 learned from data instead of hand-set:

How the digital twin is simulated

No physical mine is connected here. This page runs a software model of Node A, B and C: each tick it generates synthetic tilt / vibration / temperature values the same way real MEMS sensors would, using idle jitter plus an event profile (subsidence or fault) you trigger.

That synthetic data is pushed through the same logic the ESP32 firmware runs on-device: per-node risk classification, then a mutual-consistency check across the 3 nodes (self-calibration / drift suppression), exactly as described in the self-calibration engine on the technical-approach slide.

Reading the pipeline

Packets travel continuously left to right — sensor cluster → ESP32 edge node → LoRa radio → solar gateway → MQTT broker → AI risk engine → control-room dashboard — mirroring the sensing / edge / communication / data & analytics / validation layers from the feasibility slide.

When 2-of-3 nodes agree, the risk engine box and dashboard status dot turn amber or red together; a single outlier node is flagged as drift and suppressed instead of raising a false alarm.

Red-alert escalation dynamics

Crossing a threshold does not itself mean evacuation. The system escalates through NORMAL → WARNING → CRITICAL → EVACUATION, and only fires the evacuation signal once CRITICAL has been corroborated continuously for 5 seconds (rule R6) — a dwell timer that filters out a single spike.

On escalation it fires a fixed automated sequence — siren, safe-route line to the shaft, barrier lowered at the entrance, and a rockfall at the confirmed crack — logged as discrete ACTION entries, not just a colour change. Stand-down only happens once the readings fall back under threshold, not the instant they dip.
